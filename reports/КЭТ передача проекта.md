## 1. Что за проект

NEON REQUIEM: 3D-файтинг на Three.js + TypeScript + Vite под Android WebView.
Одна героиня, Кэт (Caitlin), против 15 монстров на 5 аренах. Некоммерческий

Задача этой ветки: **довести Кэт до полной анимации уровня MK1 из реальных
захваченных движений людей**, без ручных ключей и без генерации моделью.
Требования владельца по характеру: походка «сексуально, как по подиуму»; удары мощные;
нужны кувырки, шпагат, вертикальный подъём ноги с ударом из этого положения.

### Инструменты (`tools/anim/`, все на numpy и стандартной библиотеке, без GPU)

- **`dump_rig.py`** — скелет GLB в таблицу суставов: родители, rest-поза (трансляция +
  кватернион), индексы кистей и стоп, высоты лодыжек, длины сегментов, флаг двойной лодыжки.
- **`asf_amc_to_bvh.py`** — конвертер CMU ASF/AMC → BVH на чистом Python. Перебазирует
  вращения из собственной оси кости (`L = C·M·C⁻¹`), потому что в BVH нет per-bone axis.
- **`cmu_index.py`** — скрейпер страниц субъектов CMU в подписанный каталог
  (текстовый индекс `cmu-mocap-index-text.txt` отдаёт 404).
- **`retarget_cmu.py`** — главный: ретаргет BVH на риг Кэт в headless Blender.
- **`mc_correct.py`** — семплирует клип, FK, разметка контактов стоп, метрики:
  скольжение, уход лодыжки под bind, парение, диапазон таза. `--measure-only` — без солвера.
- **`leg_stretch.py`** — проверка каждого кадра против досягаемости костной цепи.
  Не нуждается ни в детекции контактов, ни в оценке пола.
- **`bvh_to_viewer.py`** — упаковка BVH в компактный JSON для браузерной смотрелки.
- **`apply_npz.py`** — запекание движения на арматуру и экспорт GLB через Blender.
- **`cmu_jobs/*.tsv`** — рецепт каждого набора: трайл, старт, длительность. Путь к BVH
  оставлен как `${BVH}`, поэтому наборы пересобираются после свежей закачки CMU.

### Метод ретаргета (`retarget_cmu.py`)

Переносится **изменение** источника от его собственной rest-позы, наложенное на её rest:

```
delta(t)      = src_global(t) · src_global(rest)⁻¹
tgt_global(t) = delta(t) · tgt_global(rest)
tgt_local(t)  = parent_tgt_global(t)⁻¹ · tgt_global(t)
```

Так сохраняются её пропорции, линия плеч и каблучная лодыжка, а движение едет сверху.
Это тот же принцип, что в retarget pose у UE5 IK Retargeter.

**Каноническая retarget-поза** (против кривизны): каждая пара левых и правых костей
заменяется средним между одной и зеркалом другой (`mirror(q) = (w, x, −y, −z)`),
а центральная цепь доворачивается так, чтобы линия тазобедренных суставов легла на
мировую ось X. Коррекция вышла **+12.16°** — совпала с 12° рыскания из аудита.

**Клипы in-place** по соглашению игры: горизонтальное перемещение не переносится,
только подъём и опускание таза, масштабированное по длине ноги (k ≈ 1.04).
Затем сглаженный проход прижатия к полу.

Маппинг костей CMU → Кэт — 22 пары, в `BONE_MAP` внутри файла. Остальные 116 костей
(твист, хелперы, `phys_*`, пальцы, лицо) остаются в rest — их добавляет рантайм игры.

- **71 клип прошёл контроль досягаемости**: ни один кадр ни одного клипа не просит
  кость растянуться. Проверено против её собственных длин — 829.65 мм слева, 851.76 справа.
- **Инструменты независимо воспроизвели числа аудита** с точностью до десятой миллиметра:
  бедро→лодыжка 827.87 / 849.93, бедро→голень 415.72, голень→лодыжка 413.93,

  рыскание таза 12.16°, масштаб ног k = 1.0392 против 1.03 в аудите.

  Это прямая замена мужскому ACCAD Male2, с которого сняты почти все её удары.

## 6. Что НЕ получилось — разбор вердикта владельца

### 6.1 «Руки перекрещиваются, входят друг в друга»

**Причина установлена.** Аудит, раздел 1, пункт 4: ширина её бёдер с юбкой ~48 см, а
плечевые суставы на ±0.13–0.15 м. Руки среднего актёра, опущенные вдоль тела,
**геометрически проходят сквозь её бёдра**. Аудит прямо называет лечение: постоянное
смещение в retarget pose — Грок отводил руки на **22°**.

**В `retarget_cmu.py` этого отведения нет.** Каноническая поза делает только
симметризацию пар и доворот таза. Это первое, что надо добавить: в `canonical_rest()`
домножить `clavicle_*` / `upperarm_*` на отведение ~22° вокруг оси «вперёд», со знаком
по стороне. Аудит предупреждает: большее отведение начинает читаться как «руки колесом»,
и остаётся касание кисти о бедро до 15 мм на одном кадре ходьбы.

**Дополнительно:** у игры есть слой `BodyClearance` и `BustClearance` в рантайме, которых
в смотрелке нет. Часть пересечений в игре снимется сама. Проверять надо в белой комнате.

### 6.2 «Глючат меши»

**Причина почти наверняка — отсутствие деформационного слоя.** Ретаргет пишет 22 кости.
Остальные 116 остаются в rest, в том числе **твист-кости и хелперы**, которые в игре
ведёт `DeformRig` (твист −0.5 / 1.0, хелперы 0.5), а также `SpringSystem` для `phys_*`,
корректирующие формы, отталкивание груди и тела, активный регдолл на Jolt.

В браузерной смотрелке ничего этого нет, поэтому скин схлопывается на плечах, локтях и
бёдрах — классический «candy wrapper» на предплечье. Аудит отдельно отмечает: эффект
скрутки **весами не лечится в принципе**, нужен твист-слой.

**Что делать:** судить клипы не в моей смотрелке, а в белой комнате
(`tools/whiteroom`, `npx vite --config tools/whiteroom/vite.config.mjs`) или в лаборатории,
где эти слои работают. Если глючит и там — тогда это дефект клипа, и надо смотреть
конкретные кости.

### 6.3 «Походка неровная»

Три возможные причины, по убыванию вероятности:

1. **Отведение рук отсутствует** (6.1) — корпус читается кривым, потому что руки
   висят внутри силуэта.
2. **Я взял окна произвольно**, по 3–4 секунды с произвольного старта
   (`tools/anim/cmu_jobs/*.tsv`). Цикл шага не вырезан и петля не замкнута.
   У Грока в `tools/grok/retarget/layers.py` это отдельные слои: вырезка цикла по
   лучшему совпадению позы, закрытие петли с линейным распределением остатка.
   **Моего ретаргета этого нет вообще** — клипы просто обрезаны по времени.
3. **Нет IK ног к запечённым контактам.** Мой проход только двигает таз по вертикали;
   стопа не фиксируется. У Грока это двухкостный IK к точкам контакта с постановкой
   стопы в каблучную bind-позу, повёрнутую по курсу, плюс просвет подошвы ≥ 1–12 мм.

### 6.4 «Непонятно, где зад, где вперёд»

Клипы **in-place**: горизонтальное перемещение не переносится, персонажа двигает игра.
В смотрелке игры нет, поэтому она шагает на месте и направление не читается.
Это сознательное решение по контракту (аудит §5, шаг 8), а не баг, но для оценки
походки глазами нужен либо перенос травела, либо движение камеры, либо просмотр в игре.

**Проверить отдельно:** доворот таза на 12.16° берётся от ближайшей оси. Если у какого-то
клипа источник развёрнут иначе, знак может уйти. Ранняя версия снимала 167.84° и
развернула бы её задом — поймано до показа, но проверить на каждом клипе стоит.

### 6.5 Прочее, что не сделано

- **Шпагата нет.** В CMU слово «split» не встречается ни в одном трайле (проверено по
  реальным описаниям), в SFU нет. Реальный вертикальный вынос на 180° есть в **MOYO**:
  `Standing_Split_pose_or_Urdhva_Prasarita_Eka_Padasana_-a` (224 кадра) и `-b` (227).
  Посадка собирается из `Low_Lunge_pose_or_Anjaneyasana_-b/-c/-d` и
  `Bound_Angle_Pose_or_Baddha_Konasana_-d/-e`. **Нужна регистрация на moyo.is.tue.mpg.de.**
- **Оружейные 14 клипов** (`lab_fb_1/2/3`, `lab_saw_*`, `lab_sp_*`, `lab_throw*`) остаются
  на ручных ключах. Реального источника для бензопилы и пушки в открытом мокапе нет:
  в Bandai только `slash_normal` два тейка.
- **Покадровый тайминг боя** — окна startup/active/recovery, кадры удержания на контакте,
  окна отмен — не трогался вообще. Это 100–300 часов ручной работы и ни один инструмент
  этого не делает. Без него ощущение боя не появится, какой бы плавной ни была анимация.
- **Лицо** не анимируется этими клипами: `labFace`, `src/lab/face.ts`, `faceDriver.ts`
  живут отдельно.

## 7. Заблокировано

**Сборка `MotionCorrection`** остановлена классификатором окружения с причиной
«Code from External» — это компиляция и установка внешнего C++-расширения через
`pip install .`. Снять может только владелец правилом в настройках Claude Code;
словами в чате это не снимается. Все зависимости уже стоят, из сети ничего не нужно:

```bash
apt-get install -y libeigen3-dev          # Eigen 3.4.0 + CMake-конфиг
pip install pybind11
PB=$(python -c "import pybind11;print(pybind11.get_cmake_dir())")
cd /home/user/newtech/ardy/MotionCorrection
CMAKE_PREFIX_PATH="$PB:/usr/share/eigen3/cmake" pip install --no-build-isolation .
```

## 8. Ошибки и ловушки — чтобы не повторять

Поймано измерением, не на глаз:

1. **Сустав BVH в дальнем конце кости.** Первая версия конвертера ставила сустав в
   дистальный конец, из-за чего бедро вращалось вокруг колена. Симптом: нога источника
   0.573 м вместо 0.78. Правильно: сустав в проксимальном конце, OFFSET = вектор
   родительской кости.
2. **Разворот на 168°.** Канонизация таза снимала отклонение от +X, а линия бёдер у неё
   вдоль −X. Брать отклонение от **ближней** оси.
3. **Пол уезжал на 1.6 м** в колесе и кувырках: проход считал, что низшая стопа всегда на
   земле, а там на земле руки. Корректировать только по кадрам, где стопа реально стоит.
4. **Парсер BVH:** `{` идёт **до** `OFFSET`. Обнуление имени узла на скобке даёт пустую
   иерархию, и длины костей молча печатаются нулями.
5. **Кватернионы `q` и `−q` — одно вращение.** Сравнивать компоненты нельзя,
   только угол через `|dot|`. Иначе любой клип выглядит «анимированным» на 100%.
6. **CMU субъекты 91 и 105 — побайтово один файл** (одинаковый MD5 у `.amc` и `.asf`).
   Это не два исполнителя.
7. **Субъекта 144 нет в `allasfamc.zip`** — архив кончается на 143, качать отдельно.
8. **Красный фон строки в таблице CMU не означает брак** — он у всех строк.
9. **`cmu-mocap-index-text.txt` отдаёт 404.** Описания брать со
   `search.php?subjectnumber=NNN`, парсер — `tools/anim/cmu_index.py`.
10. **`137_04 «Cat Walk»` — изображение кошки**, не подиум.
11. **«OnHeels» и «heel-walking» в датасетах = ходьба на пятках с поднятым носком**,
    противоположность каблуку. Для её bind-позы донор — **ходьба на носках**
    (`136_27/28`, `136_05/06`, `136_13/14`).
12. **Ранжир источников по короткому шагу не годится под подиум.** Подиумный шаг длинный,
    стопа в стопу. Геометрическая модель просадки (`ankle + sqrt(leg² − (шаг/2)²)`,
    k = 1.03) полезна как **предиктор работы для IK**, а не как критерий выбора.
13. **Модель с формами лица валит three.js r137** в браузере: одна из 95 форм приходит
    без данных позиций, и `updateMorphTargets` читает имя у пустой записи. Для просмотра
    нужна копия без форм (скрипт в разделе 9); игровой файл не трогать.
14. **`vid2anim` не существует**; «23.7% боевых искусств в MotionMillion» не подтверждается.

## 9. Как воспроизвести с нуля

Окружение здесь: 4 ядра Xeon, 15 ГБ RAM, **GPU нет**, ~23 ГБ свободно.
Данные на диске контейнер не переживают — качать заново.

```bash
# Blender 4.2.3 LTS (та же версия, под которую писал Грок)
curl -L -o blender.tar.xz \
  https://download.blender.org/release/Blender4.2/blender-4.2.3-linux-x64.tar.xz
mkdir bl && tar -xf blender.tar.xz -C bl --strip-components=1

# Python 3.11 + numpy
python3.11 -m venv venv && ./venv/bin/pip install "numpy<2"

# CMU
curl -O http://mocap.cs.cmu.edu/allasfamc.zip        # 1.08 ГБ, только http
# субъект 144 отдельно:
for i in $(seq -w 1 34); do curl -O "http://mocap.cs.cmu.edu/subjects/144/144_${i}.amc"; done
curl -O http://mocap.cs.cmu.edu/subjects/144/144.asf

# таблица рига
python3 -I tools/anim/dump_rig.py public/chars/kat_tripo.glb kat_rig.json

# ASF/AMC -> BVH
python3 -I tools/anim/asf_amc_to_bvh.py --asf 144/144.asf --amc-dir 144 --out-dir bvh/

# ретаргет набора (пути в tsv — ${BVH})
BVH=./bvh envsubst < tools/anim/cmu_jobs/podium.tsv > /tmp/podium.tsv
./bl/blender -b --python tools/anim/retarget_cmu.py -- \
  --model public/chars/kat_tripo_low.glb --list /tmp/podium.tsv \
  --out public/chars/anims_cmu_podium.glb --fps 30

# контроль
python3 tools/anim/leg_stretch.py --rig kat_rig.json --glb public/chars/anims_cmu_podium.glb
python3 tools/anim/mc_correct.py --measure-only --rig kat_rig.json --glb public/chars/anims_cmu_podium.glb
```

Копия модели без форм лица для браузерного просмотра — скрипт был временным; суть:
импортировать GLB в Blender, на каждом меше `obj.shape_key_clear()`, экспортировать с
`export_morph=False`. На `kat_tripo_low.glb` убирается 361 форма, файл падает с 11.6 до 7.0 МБ.

Проверять страницу до публикации настоящим браузером:
Playwright предустановлен, но резолвится только по полному пути —
`import pw from '/opt/node-tools/node_modules/playwright/index.js'` (CommonJS, не named export).
