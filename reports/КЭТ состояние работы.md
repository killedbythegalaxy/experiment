## Что сделано

**Инструменты (мои, в ветке).** `dump_rig.py` выгружает скелет в таблицу суставов;
`mc_correct.py` семплирует клип, считает FK, размечает контакты стоп, измеряет
скольжение, уход лодыжки, парение и диапазон таза (`--measure-only` — без солвера);
`leg_stretch.py` проверяет кадры против досягаемости костной цепи;
`apply_npz.py` печёт результат на арматуру и экспортирует GLB через Blender;
`asf_amc_to_bvh.py` конвертирует CMU ASF/AMC в BVH без внешних программ;
`cmu_index.py` собирает подписанный каталог трайлов со страниц CMU;
`bvh_to_viewer.py` упаковывает BVH в JSON для браузерной смотрелки.

**Валидация.** `dump_rig.py` независимо воспроизвёл числа `docs/KAT_RIG_AUDIT_RU.md`:
бедро→лодыжка 827.87 / 849.93 мм, бедро→голень 415.72, голень→лодыжка 413.93,
лодыжка 257.41 мм, `ball_r` выше `ball_l` на 15.48 мм, досягаемость 829.65 / 851.76
(асимметрия 22.11 мм). 139 узлов, двойная лодыжка определяется автоматически.
Конвертер ASF/AMC проверен физически: высота таза медиана 83.3 см, бедро 37.2 см, 120 fps.

**Измеренная инвентаризация.** `anims_lab_mocap.glb` (ветка Грока): 49 клипов, 57.0 с,

## Поправки — чтобы не повторять

Проверено измерением и оказалось **не** дефектом:

1. **Растяжение ноги.** Ни одного превышения досягаемости цепи ни в одном из 103 клипов.
   Первая оценка «+26 мм на `lab_low_kick`» была ошибкой метода: разность высот вместо
   3D-расстояния от сустава бедра.
2. **Замороженные ноги в оружейных клипах.** Ноги анимированы везде, отход от rest-позы
   60–160°. Первый тест был неверен: сравнивались компоненты кватернионов, а `q` и `−q` —
   одно вращение; мерить надо угол через `|dot|`.
3. **Рывок на `Root`.** Ручные наборы пишут константный трек, равный rest-повороту
   (−0.7071, 0, 0, 0.7071). Избыточная дорожка, не разница поведения.

Факты, которые оказались неверны в источниках:

4. **Субъекты CMU 91 и 105 — побайтово один файл** (одинаковый MD5 у `.amc` и `.asf`).
   Это не два исполнителя на одном протоколе. Дубликат из отбора убран.
5. **Субъекта 144 нет в `allasfamc.zip`** — архив заканчивается на 143. Качается отдельно
   с `http://mocap.cs.cmu.edu/subjects/144/144_NN.amc` (34 трайла + `144.asf`).
   Подпись «punching female» подтверждена со страницы CMU.
6. **Кувырок назад существует** — `90_01 bkwd summersult`.
7. **Красный фон строки в таблице CMU не означает брак** — он у всех строк.
8. **`cmu-mocap-index-text.txt` отдаёт 404**; описания брать со `search.php?subjectnumber=NNN`.
9. **`137_04 «Cat Walk»` — изображение кошки**, не подиум (лежит рядом с Chicken и Dinosaur).
10. **«OnHeels» и «heel-walking» означают ходьбу на пятках с поднятым носком** —
    противоположность обуви на каблуке. Для её bind-позы правильный донор — **ходьба
    на носках** (`136_27/28`, `Tiptoe_FW`). Мой же тезис «постановка с пятки» для подиума
    тоже неверен: на каблуке контакт пяткой короткий, стопа уже оттянута.
11. **Ранжир походок по короткому шагу не годится под подиум.** Подиумный шаг длинный,
    стопа в стопу, с ротацией таза. Геометрическая модель просадки остаётся полезной,
    но как **предиктор работы для IK**, а не как критерий выбора. Рекомендация
    `walk_proud_001` снята.
12. **Баг парсера BVH, который молча портил замеры:** в BVH `{` идёт до `OFFSET`,
    и обнуление имени узла на скобке давало пустую иерархию. Из-за него в раннем
    ранжире колонка длины ноги печаталась нулём. Исправлено в `bvh_to_viewer.py`;
    сам ранжир считался по данным движения и остался верен.
13. **`vid2anim` не существует.** **`MotionMillion` «23.7% боевых искусств» не подтверждается.**
    `Motion2MixamoRig` (`MaxLiu22`, 1747 звёзд) и `mixamo-llm-mocap` (`squall01337`,
    413 звёзд) — два разных реальных проекта.
14. **ARDY** (`nv-tlabs/ardy`, SIGGRAPH, Apache-2.0, 10 июля 2026) — real-time модель с
    той же управляемостью, что у Kimodo; чекпойнт `ARDY-SOMA-RP-30FPS-Horizon60` на 30 fps.
    В первом отчёте пропущен.

## Заблокировано правами

Сборка **`MotionCorrection`** (`correct_motion` из Kimodo и ARDY) остановлена классификатором
auto-mode с причиной «Code from External» — это компиляция и установка внешнего
C++-расширения через `pip install .`. Все зависимости уже стоят локально
(Eigen 3.4.0 через apt, pybind11 в venv, cmake 3.28, g++ 13.3), из сети больше ничего
не требуется. Команда, на которой остановились:

```bash
PB=$(/home/user/newtech/venv/bin/python -c "import pybind11;print(pybind11.get_cmake_dir())")
cd /home/user/newtech/ardy/MotionCorrection
CMAKE_PREFIX_PATH="$PB:/usr/share/eigen3/cmake" \
  /home/user/newtech/venv/bin/pip install --no-build-isolation .
```

Почему это стоит разблокировать: `correct_motion` **рига-агностичен** — принимает список
родителей суставов и rest-позу каждого, то есть работает прямо на её 138-костном риге,
без SMPL и SOMA, и её каблук входит как часть констрейнта. Есть флаг
`has_double_ankle_joints` ровно под её `foot_*` + `ball_*`. CPU, torch не нужен: C++
мутирует плоские numpy-массивы на месте. `mc_correct.py` написан под этот вызов целиком,
не хватает только собранного модуля. Альтернатива без внешнего кода — реализовать тот же
алгоритм на `scipy.sparse.linalg` (разреженный МНК по траектории с весами скорости плюс
двухкостный IK к размеченным контактам).
